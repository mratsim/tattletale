# regex_engine

General regex infrastructure for Tattletale:

- a pattern parser
- a Thompson NFA compiler
- a priority-preserving leftmost-first matcher with a memoized
  frontier-DFA deterministic compile

Extracted from the tokenizer workspaces. Tokenizer knowledge stays
with the consumers (pattern constants, family chains, split semantics).

## What it provides

The entry point [`regex_engine.nim`](regex_engine.nim) imports
and re-exports the `src/` modules. The root shim
[`../regex_engine.nim`](../regex_engine.nim) re-exports the package.

### Pattern engine — `src/regex_core.nim`

| component | contract |
|---|---|
| **Parser** (recursive descent) | supported regular subset: the alternation, concatenation, non-capturing groups, caseless groups `(?i:...)`, single-codepoint negative lookaheads `(?!\S)` / `(?!\p{Script=Han})`, the `$` assertion (PCRE2 before-final-LF semantics), character classes with `\p{...}` members and complements, and the `* + ? {m,n}` quantifiers, greedy, with the possessive suffix `+` accepted and compiled as greedy (extent-equivalence justification in the module header). Lazy quantifiers are rejected at compile time |
| **Leftmost-first simulation** | a Thompson NFA whose threads carry the pattern-preference order, expanded depth-first per slot, with the cut rule. An acceptance kills lower-priority threads, a surviving higher-priority acceptance overrides the recorded extent. Reproduces PCRE2 backtracking-priority match extents without state explosion and without exponential backtracking. NOTEMPTY handling discards a zero-width acceptance, mirroring PCRE2 NOTEMPTY |
| **Frontier DFA** | the default scan driver memoizes the simulation's ordered frontiers and per-symbol transition tables, so steady-state matching is a table walk while preserving leftmost-first extents by construction. A plain powerset DFA is a longest-match machine and cannot preserve them. The NFA simulation remains the parity suites' equivalence reference and the fallback when the lazy determinization cap is hit (same output, step-for-step replica). The full contract lives in the `regex_core` module header |
| **Scan machine** | `RegexScanner` + `initRegexScanner` + one `items(var)` iterator yielding `(start, stop)` match spans, the object + ctor + ONE-iteration machine shape over `nextMatch`. The cursor advances before each yield (resume discipline), no allocation, window subscans via `winLo` / `winHi` |
| **Scan drivers** | `nextMatch` is the DFA-backed leftmost scan in PCRE2 find-all semantics and returns `(start, stop)` or `(-1, -1)`. `nextMatchNfa` is the simulation variant. `dfaStats` / `dfaMemoryEstimate` are the build receipts. `matchAt` takes one anchored attempt at a fixed codepoint boundary with window-bounded dollar semantics. The pattern-split pre-tokenizer scans through it |

### Unicode property tables — `src/regex_unicode_tables.nim`

Sorted, disjoint, inclusive codepoint ranges:
`\p{L} Lu Lt Lm Lo Ll M N P S \s \p{Script=Han}` plus the simple-fold
partner sets for the contraction letters.

- Generated by querying the bundled PCRE2 engine (`workspace/pcre2`)
  for every codepoint, so the ranges match the exact UCD PCRE2 resolution.
- The generator [`tests/testgen/gen_unicode_tables.nim`](tests/testgen/gen_unicode_tables.nim)
  runs twice per regeneration, byte-identical outputs required before
  committing. Do not hand-edit.
- The `\s` variant table (`RustSpaceRanges`, the Rust regex White_Space definition)
  lives in `regex_core` for callers whose reference engine is the Rust regex family.

## Tests

| suite | coverage |
|---|---|
| `tests/t_engine_semantics.nim` | parse/compile determinism, class bitmap vs range-scan equivalence, PCRE2 reference parity (direct replica of the bundled engine's compile + match flags) over engine-relevant patterns, adversarial LCG fuzz rows, leftmost-first-vs-longest divergence rows, NOTEMPTY rows, `$`-before-final-LF rows, the two `\s` variants (U+180E included), DFA == NFA equivalence, the compile-error model |
| `tests/t_engine_scanner.nim` | `RegexScanner` machine conformance: scan-order spans, window bounds, resume discipline, post-drain emptiness, parity with the raw `nextMatch` loop |

Run:
  `nim test_regex_engine` (bounded fuzz rounds, wall receipts printed).

## Wall budget

- Every suite prints a `wall <seconds>` receipt at the end.
- Committed run with release builds:
  family total 0.1 s, t_engine_semantics 0.10 s, t_engine_scanner 0.001 s.
- The Unicode table generator is a separate manual run, the test task
  does not scan it (its full UCD query takes < 1 s build included).
